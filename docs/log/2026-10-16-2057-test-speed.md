# Quick tier speed-up (owner ask: "tests are sprawling")

The quick tier had grown to 610 tests in 119 files and 3 min 14 s on a 4-core cloud container, past the 2-minute budget (`AGENTS.md` §5). Measured where the time went before changing anything, by timing `generateMap`, `createGame` and `step` across one full run:

- **Map generation: about 41% of all CPU time.** 992 maps at ~260 ms each under load, mostly the same few worlds (seed 7, small, two players) built again for every test.
- **Simulation (`step`): about 34%.** 546k ticks, a third of them in `sim.test.ts`.
- Importing and transforming modules: about 6%. So merging test files would tidy the folder but barely save time.

What changed:

1. **`src/sim/mapgen.ts` is about 27% faster** with the same output. The neighbour offsets were fresh array literals inside per-tile loops, and five searches built and sorted a list of every start's distance for every tile; now flat offset tables and a `nearestTwo` scan. A fingerprint (SHA-1 of the whole `MapData`) of 432 maps (6 map types × small/medium × 2–4 players × with/without deposits × 6 seeds) is identical before and after. Players get faster match starts too.
2. **`placeProblem` (`src/sim/grid.ts`) skips the relic/post/ruin/landmark checks** when none is near the footprint (`keepClearNear`), one box test per footprint instead of four list scans per tile. About 14% of an AI match was spent there, mostly the computer's site searches. Checksums after 10 game minutes of four AI matches (continental, sea, lakes and highlands; 2–4 players) are identical before and after.
3. **`tests/setup/map-cache.ts`** (a vitest setup file) remembers each generated world for the rest of its test file and hands every caller a `structuredClone`, so no test can change another's world. Files run in separate processes, so the cache is per file (1–11 hits a file in a sample).
4. **"a hard opponent beats an easy one"** (two 40-minute computer matches, 43 s) moved unchanged from `tests/sim.test.ts` to `tests/slow/ai-opponent.test.ts`. The determinism replay and the static scan stay in the quick tier.

Result: 1 min 51 s wall, 6 min 19 s CPU (was 10 min 45 s), 609 tests green; the moved test passes in the slow tier.

Not done, for whoever carries this on:

- **Several tests play the same AI match twice** to compare (`sim.test.ts` determinism, `naval.test.ts` two runs, save/load in `features`, `naval`, `ai-web`), 8–15 s each. One shared "record a match, then replay and load it at points" helper could cover them in one pass.
- **Duplicated helpers:** `meadow` in five files (`animals`, `boar`, `carrion`, `herds`, `wild`), `setup` in five, `fixture` in four, each slightly different. A `tests/helpers.ts` with `openGround(s, { radius, awayFromTowns, unclaimed })` would cut the sprawl without changing what's tested.
- Under vitest each imported constant (`T_GRASS`, `R_NONE`, …) is read through a getter (vite's module runner), so sim code runs about 2× slower in tests than bundled. Not worth bending the rules code for.
