# Cloud saves (#290)

The owner asked for cloud saves (chat with Claude Code, 2026-10-15).

- **Server:** `worker/vault.ts`, a SQLite-backed Durable Object class `Vault`, one per save key, bound as `VAULTS` (`wrangler.toml`, migration `v2`, only adds a class). Routes in `worker/index.ts`: `GET /api/vault/KEY`, `GET|PUT|DELETE /api/vault/KEY/N`. The key, the slot and a declared size are checked before any vault is touched; the vault measures the body itself too. Every visit moves an alarm a year ahead; when it rings, the vault is emptied.
- **Shared rules:** `src/net/vault.ts` (key shape, 3 slots, 1.5 MB gzipped cap). **Browser:** `src/net/cloud.ts` (this browser's key in `localStorage` `ages-vault-key`, gzip with `CompressionStream`, fetch calls).
- **Game:** `src/main.ts`, "Cloud saves" section. The save text is the local save's (`saveText`/`readSave`, same `SAVE_V`), so the bump rule covers both.
- **Sizes:** a large four-player Hard match at 25 minutes serializes to 978 KB, which gzips to 150 KB.
- **Previews:** they have no Durable Objects, so the panel says "Cloud saves are not available here." The same goes for `npm run dev` (no Worker): use `npm run build && npx wrangler dev`.
- **Seen:** under `wrangler dev` in headless Chromium. On the title, the panel shows 3 empty slots and the key. In a match, Save here filled slot 1. A fresh browser profile took the first key (typed in lower case) and loaded slot 1 into a running match, with no page or console errors.
- **Not seen:** the live deploy, or a real phone.
